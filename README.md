# Пеку Хлеб — «Что печём?»

**Отдельный маленький сайт для сотрудников**, полностью независимый от административной панели, NFC, вечерних/утренних отчётов и основного сайта.

## Что видит сотрудник

- Две самостоятельные страницы, **Образцовая** `/bake-obrazcovaya.html` и **Челюскина** `/bake-chelyuskina.html`.
- Дата выпечки с компактным календарём (по умолчанию завтра, расчёт по московскому времени).
- Крупные плитки по три в ряд, самые ходовые виды хлеба — первыми.
- Кнопка «Отправить» закреплена внизу, перед отправкой — окно подтверждения.
- После успешной доставки — «План выпечки отправлен в Telegram».

**В Telegram** приходит одно аккуратное сообщение: «ПЕКУ ХЛЕБ · ПЛАН ВЫПЕЧКИ», пекарня, дата, выбранные виды хлеба и их количество. Никаких имён сотрудников, учёта по штукам и связей с другими проектами.

## Размещение

1. Создать отдельный проект Vercel из репозитория `aaleksej471-gif/pekuhleb-bread-plan` (ветка `main`). Framework Preset — Other.
2. В Vercel → Project → Settings → Environment Variables создать **четыре секрета**, доступных для Production:
   - `TELEGRAM_BOT_TOKEN` — токен Telegram-бота, который добавлен в нужную группу и может отправлять сообщения.
   - `TELEGRAM_CHAT_ID` — ID нужной Telegram-группы.
   - `BREAD_KEY_OBRAZCOVAYA` — случайный секрет для рабочей ссылки Образцовой.
   - `BREAD_KEY_CHELYUSKINA` — другой случайный секрет для рабочей ссылки Челюскина.

   Секреты не должны попадать в GitHub, сообщения в чате или публичные страницы. После изменения окружения нужно сделать новый deploy.

3. Рабочие ссылки для QR содержат закрытый ключ только в адресе (его нет в файлах GitHub):
   - `https://<адрес-проекта>/bake-obrazcovaya.html?k=<BREAD_KEY_OBRAZCOVAYA>`
   - `https://<адрес-проекта>/bake-chelyuskina.html?k=<BREAD_KEY_CHELYUSKINA>`

   QR-коды с такими ссылками разместить **со стороны сотрудников** над хлебными витринами. Ключи не печатать как текст и не публиковать QR в открытом доступе.
4. Отправить пробный план и проверить появление одного сообщения в Telegram-группе. Затем распечатать два QR-кода А6.

Пока параметры окружения не настроены, интерфейс работает для выбора и проверки, **но реальной отправки не будет**. При отсутствии ключа страница попросит открыть рабочую ссылку с QR-кода.

## Проверка кода

```bash
npm run check
```

Серверный маршрут `POST /api/send` проверяет тип запроса, пекарню, токен рабочей ссылки, дату выпечки и названия хлеба по закрытому списку. При ошибке Telegram сотрудник получает сообщение об ошибке вместо ложного «отправлено».

## Безопасность и эксплуатация

- Каждая пекарня имеет собственный секрет; ссылка одной точки не может подписать план другой.
- API и Telegram-бот работают только на сервере; токен Telegram не передаётся браузеру.
- Повторное нажатие «Подтвердить» во время отправки блокируется, а успешно отправленный в текущем сеансе список не может быть повторно отправлен без изменения даты или хлеба.
- Между разными устройствами нет общей истории или серверного хранилища планов. При сетевой ошибке после передачи запроса Telegram повторная отправка **может** привести к дубликату — перед повтором стоит проверить группу.
- При утере рабочего QR следует заменить секрет соответствующей пекарни и перепечатать её QR.

Проект не читает и не изменяет данные других систем «Пеку Хлеб».
